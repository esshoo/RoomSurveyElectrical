# v1.9.25 — Build 46.1 Safe Pause, Resume, and Relocalization

Build 46.1 establishes the first operational part of Build 46. It turns spatial scanning from a finish-or-lose workflow into a resumable workflow without modifying the original RoomPlan data directly.

## Safe pause and save

During a live RoomPlan scan the user can choose **إيقاف مؤقت وحفظ**. The capture session stops, the latest processed room or last live room snapshot is saved, and the current ARWorldMap is requested before the AR session is paused.

The same safe-save path is triggered when the application leaves the active foreground. A UIKit background task gives RoomPlan processing and project persistence additional time before iOS suspends the app.

## Persisted continuation state

`RoomProject` now has an optional `scanContinuationState`. It stores:

- pause reason: manual, thermal safety, application background, or interruption;
- pause date;
- last successful world-map capture date when available.

The field is optional, so projects created by earlier builds decode without migration failure. Completing or accepting a scan clears the continuation state.

## Resume and relocalization

A paused scan is highlighted in the room viewer. Opening it starts ARWorldMap relocalization before RoomPlan is run again. The UI explains the current tracking state and offers a manual way to stop the relocalization attempt without discarding the saved room.

After the 35-second timeout the app no longer turns the scan into a terminal error. It pauses AR tracking and offers:

- retry relocalization;
- accept the saved partial room;
- return to the project.

A missing or unreadable ARWorldMap follows the same protected path. The saved room remains available.

## Thermal integration

Thermal stops while scanning use the same persisted continuation state and saved world map. Thermal stops while relocalizing also record a thermal pause before entering the cooling screen.
