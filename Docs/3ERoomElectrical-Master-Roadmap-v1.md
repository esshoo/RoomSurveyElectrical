# 3ERoomElectrical — Master Roadmap v1

**Baseline:** v1.9.23 — Build 44
**Purpose:** تنفيذ نظام تحديث وتحرير المشروع بصورة تدريجية دون نسيان المتطلبات أو كسر الميزات المستقرة.

---

## 1) قواعد التنفيذ الملزمة

1. لا يبدأ أي Build جديد قبل تثبيت خط الأساس السابق واختبار الترحيل وفتح المشاريع القديمة.
2. لا تُعدّل بيانات المسح الأصلية مباشرة؛ كل تعديل يُحفظ في طبقة أو Change Set قابل للمراجعة والتراجع.
3. إنشاء نسخة استعادة تلقائية قبل الدمج أو الاستبدال أو الحذف الجماعي.
4. إعدادات كل ميزة تُبنى على مستويات: التطبيق ← المشروع ← الغرفة/المسحة ← العنصر.
5. القيمة الأكثر تخصيصًا تتغلب على القيمة الموروثة، مع زر للرجوع إلى إعداد المستوى الأعلى.
6. لا تُغيّر ملفات DXF/PDF/GLB إلا عندما تكون المرحلة مرتبطة بها صراحةً.
7. لا تُحذف صور أو مسحات أو عناصر قديمة نهائيًا أثناء التحديث؛ تُعلّم كمستبدلة أو محذوفة داخل السجل حتى يتم التأكيد النهائي.
8. كل Build يخرج بمصدر كامل وPatch منفصل وسجل تغييرات ومعايير قبول واضحة.
9. لا يُعتبر Build مكتملًا قبل اجتياز فحوصات المصدر، الترحيل، سلامة الحزمة، واختبار فعلي على جهاز عند توفره.
10. أي طلب جديد يُضاف أولًا إلى هذه الخطة مع تحديد مرحلته واعتمادياته قبل تنفيذه.

## 2) حالة خط الأساس الحالية

### موجود في المصدر الحالي

- إعدادات الأداء وجودة المسح.
- إعدادات الحماية الحرارية.
- الحفظ الوقائي ومحاولة حفظ ARWorldMap.
- طبقة صور الحوائط في 2D و3D.
- جودة الصور المركبة وتحديد الأجزاء الضعيفة.
- تصدير GLB بخامات الحوائط.

### يحتاج اختبارًا ميدانيًا قبل التوسع

- الانتقال الحقيقي بين حالات الحرارة على iPhone.
- الحفظ والاستكمال بعد الإيقاف الحراري.
- نجاح ARWorldMap Relocalization في المكان نفسه.
- فتح جلسة إعادة تصوير الأجزاء الضعيفة فعليًا وربط الصور الجديدة بالمربعات الصحيحة.
- فتح المشاريع القديمة بعد إضافة بيانات الإعدادات والخرائط الجديدة.

---

## 3) بنية المشروع المستهدفة

كل مشروع يتكون من طبقات مستقلة:

1. **Original Scan Layer** — نتيجة RoomPlan الأصلية غير المعدلة.
2. **Architectural Corrections Layer** — الحوائط والفتحات والأبواب والشبابيك المصححة أو المضافة.
3. **Element Layers** — الكهرباء ثم أي أنواع عناصر مستقبلية.
4. **Photo & Material Layer** — صور الحوائط والألوان والخامات.
5. **Furniture & Design Layer** — الفرش الواقعي والمجسمات المضافة.
6. **Presentation Scenes** — حالات عرض محفوظة بدون نسخ كامل للمشروع.
7. **Change History** — جلسات الإضافة والتعديل والحذف والاستبدال.
8. **Recovery Snapshots** — نقاط استعادة قبل العمليات الخطرة.

---

## 4) نظام الإعدادات

### مستويات الإعداد

- **App Defaults**: القيم الافتراضية للمشروعات الجديدة.
- **Project Settings**: إعدادات مخصصة للمشروع.
- **Room/Scan Settings**: اختلافات الغرف أو المسحات.
- **Element Overrides**: استثناءات عنصر واحد.

### متطلبات الواجهة

- إظهار هل القيمة موروثة أم مخصصة.
- استعادة القيمة الموصى بها.
- الرجوع لإعداد المستوى الأعلى.
- نسخ إعدادات غرفة أو عنصر إلى أخرى.
- حفظ الإعدادات كقالب.
- تقسيم الخيارات إلى: أساسي، متقدم، مخصص.

# 5) خطة الإصدارات

## Build 45 — الأساس المشترك لتحديث المشروع

### النطاق

- نماذج AppDefaults وProjectSettings وRoomSettings وElementOverrides.
- محرك وراثة الإعدادات وحساب القيمة الفعلية.
- Project Layers العامة وحالات إظهار/إخفاء/قفل الطبقة.
- Change Set عام يدعم: إضافة، تعديل، حذف، استبدال، تأكيد وجود.
- سجل تعديلات داخل المشروع.
- Recovery Snapshot قبل العمليات الخطرة.
- شاشة أوضاع المشروع الأساسية.
- مؤشر ARWorldMap: متاحة/غير متاحة/آخر حفظ.
- ترحيل المشاريع القديمة بقيم افتراضية بدون فقد بيانات.

### لا يشمل

- رسم الحوائط الفعلي.
- محرر تجميع المسحات.
- مكتبة فرش.
- QR أو خادم مشاركة.

### معيار القبول

- المشروع القديم يفتح بدون تغيير بصري أو فقد بيانات.
- يمكن إنشاء إعداد مشروع مخصص ثم الرجوع للإعداد الموروث.
- يمكن إنشاء Change Set وحفظه والتراجع عنه.
- يمكن قفل وإخفاء كل طبقة بدون حذف محتواها.

## Build 45-HF1 — تصحيح اتجاه صور الحوائط

### النطاق

- تصحيح انعكاس مواضع الفتحات والكهرباء والفرش فوق صورة الحائط.
- إضافة قلب أفقي وقلب رأسي مستقلين لكل حائط.
- استخدام التحويل نفسه في معاينة الصور والعرض 2D و3D وتصدير GLB.
- جعل التصحيح الأفقي هو الوضع التلقائي للمشاريع الحالية والجديدة، مع إمكانية إلغائه يدويًا لكل حائط.
- عدم تعديل ملفات الصور الأصلية أو بيانات RoomPlan؛ يحفظ التصحيح كإعداد عرض قابل للتراجع.

### معيار القبول

- الباب والمفتاح والفتحات تظهر في الجهة المطابقة للصورة.
- يمكن تبديل القلب الأفقي والرأسي وحفظهما ثم إعادة فتح المشروع بنفس النتيجة.
- المشاريع القديمة تفتح بدون فقد الصور، وتطبق التصحيح التلقائي الافتراضي.
- العرض 3D وتصدير GLB يستخدمان اتجاه الصورة المختار للحائط.

## Build 46 — الإيقاف والاستكمال وإعادة التموضع

### حالة التنفيذ الحالية

- **Build 46.1:** الإيقاف اليدوي الآمن، الحفظ عند مغادرة التطبيق، حفظ سبب ووقت التوقف، واجهة المسح المتوقف، إعادة التموضع مع إعادة المحاولة، وحماية الجزء المحفوظ عند الفشل.
- **Build 46.1-HF1:** تحسين إعادة التموضع بخريطة AR جيدة، Anchor مرجعي، صورة وآخر حائط وأبعاده ومركزه واتجاهه، مع موقع وبوصلة اختياريين وإعدادات صرامة.
- **Build 46.1-HF2/HF3:** إصلاحات تجميع Xcode فقط دون تغيير منطق إعادة التموضع أو البيانات.
- **Build 46.2:** نقاط الحفظ الدورية القابلة للضبط أثناء المسح الحي.
- **Build 46.3:** إصلاح مسار إعادة تصوير الأجزاء الضعيفة وإعادة بناء صورة الحائط بعد الاستبدال.

### النطاق

- زر إيقاف مؤقت وحفظ أثناء المسح.
- نقاط حفظ دورية قابلة للضبط.
- استكمال بعد الحرارة أو الإيقاف اليدوي أو مغادرة التطبيق.
- شاشة Relocalization واضحة قبل تشغيل RoomPlan.
- مهلة إعادة التموضع وإعادة المحاولة أو اعتماد الجزء المحفوظ.
- إصلاح مسار إعادة تصوير الأجزاء الضعيفة ليفتح جلسة التصوير فعليًا.
- إعادة بناء صورة الحائط بعد نجاح الاستبدال.

### معيار القبول

- إيقاف جلسة مسح ثم فتح المشروع واستكماله في المكان نفسه.
- عدم حذف الجزء المحفوظ عند فشل إعادة التموضع.
- زر إعادة تصوير الأجزاء الضعيفة يفتح الكاميرا ويعرض المطلوب فقط.

### قرار معماري للاستمرارية والعرض

- إعادة التموضع التلقائية تتم على `ARSession` مستقلة أولًا، ولا تُنشأ `RoomCaptureView` إلا بعد عودة التتبع إلى الحالة الطبيعية.
- وضع العرض الافتراضي داخل التطبيق يعتمد على إحداثيات المشروع المحفوظة ولا يتطلب GPS أو `ARWorldMap`.
- العرض فوق المكان الحقيقي واستكمال المسح يستخدمان خدمة محاذاة مشتركة: `ARWorldMap` تلقائيًا، ثم محاذاة حائط/فتحة يدوية بنقطتين أو ثلاث نقاط كمسار احتياطي إذا تعذر التطابق التلقائي.
- لا يسمح بدء مقطع RoomPlan جديد في إحداثيات مجهولة ثم دمجه صامتًا مع المشروع القديم.

## Build 47 — جلسات تحديث العناصر

- Change Set باسم وتاريخ وملاحظات.
- إعدادات حسب نوع العنصر والغرفة والعنصر الفردي.

### معيار القبول

- تنفيذ جلسة مراجعة كهرباء كاملة دون تغيير الهندسة المعمارية.
- التراجع عن الجلسة يعيد جميع العناصر إلى حالتها السابقة.

## Build 52 — QR والبصمة والمشاركة المحلية

### النطاق

- Project Fingerprint ثابت وآمن.
- إنشاء QR داخل المشروع.
- قراءة QR من داخل التطبيق.
