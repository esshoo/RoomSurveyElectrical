# v1.9.24 — Project update foundation

## Scope

Build 45 establishes the shared data and persistence layer required by later scan-resume, element-update, architectural-editing, floor-alignment, presentation, furnishing, and QR-sharing builds.

## Settings inheritance

`ProjectAppDefaults` provides complete app defaults. `ProjectSettings`, `RoomSettings`, and `ElementSettingsOverride` store partial overrides. `SettingsInheritanceEngine` applies them from the least specific level to the most specific level.

Legacy project settings are converted to a project-level delta on first load, preserving the exact effective values that existed before migration.

## Project layers

`ProjectLayerState` stores persistent visibility, lock state, and opacity for each `ProjectLayerKind`. The current 2D/3D viewer consumes the applicable project-level visibility and lock settings. Existing/proposed electrical separation is represented in the data model; independent rendering is deferred to the element-update build.

## Change sets

`ProjectChangeSet` groups generic `ProjectChangeRecord` values. Records support add, modify, delete, replace, confirm-existing, and mark-missing actions. Build 45 provides session creation, completion, history, and latest-session rollback; element-specific application begins in Build 47.

## Recovery

Recovery snapshots are stored in a dedicated directory and contain the workspace JSON plus one `RoomProject` JSON record for every scan referenced by the workspace. A restore operation first captures the current state, then restores the selected workspace and scan records while preserving the current audit history and recovery index.

Large immutable assets such as USDZ, processed/raw RoomPlan JSON, ARWorldMap data, and wall-photo files remain in their project folders in Build 45. Later destructive operations must use copy-on-write filenames before replacing those assets so an older recovery record remains valid.

Recovery files are device-local in Build 45 and are not embedded in exported `.3eroom` packages. Package export strips recovery metadata and snapshot links. Imported packages retain portable project settings, layers, modes, and change-set history, but no unavailable local recovery references.

## Migration

New fields on `SurveyProject` remain optional. `normalizeFoundation` fills them, normalizes layer records, derives effective settings, and writes the migrated project back atomically.
