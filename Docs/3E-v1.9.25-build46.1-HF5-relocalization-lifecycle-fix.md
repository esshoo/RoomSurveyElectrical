# v1.9.25 Build 46.1-HF5 — Relocalization lifecycle fix

## سبب الإصلاح

كان `RoomCaptureView` يُنشأ عند إنشاء `RoomCaptureModel`، أي قبل تشغيل `ARSession` بخريطة `initialWorldMap`. هذا يخالف تسلسل RoomPlan الموثق وقد يسمح لواجهة RoomPlan بالارتباط بجلسة AR قبل انتهاء استعادة الإحداثيات القديمة.

## التسلسل الجديد

1. عند فتح مسح محفوظ تُنشأ `ARSession` عادية بدون `RoomCaptureView`.
2. تعرض `ARSCNView` بث الكاميرا فقط أثناء إعادة التموضع.
3. تُحمّل `ARWorldMap` وتُشغّل الجلسة مع `initialWorldMap`.
4. ينتظر التطبيق انتقال التتبع من `relocalizing` إلى `normal`.
5. بعد نجاح التطابق فقط تُنشأ `RoomCaptureView` جديدة فوق نفس `ARSession` ثم يبدأ RoomPlan.
6. الإيقاف والاستكمال داخل نفس الشاشة ما زالا يستخدمان نفس `RoomCaptureView` والجلسة الحية مباشرة.

## حماية جودة الخريطة

- لا تُحفظ خريطة `limited` أو `notAvailable` باعتبارها صالحة للاستكمال.
- عند توفر أكثر من لقطة، تُفضّل `mapped` على `extending`، ثم الخريطة ذات عدد نقاط المعالم الأكبر.
- يحفظ المشروع عدد نقاط الخريطة ومدى التغطية لأغراض التشخيص.

## حدود الوظيفة

وضع العرض الافتراضي داخل المشروع لا يعتمد على إعادة التموضع. أما العرض فوق الموقع الحقيقي واستكمال RoomPlan فيستخدمان محاذاة مكانية؛ وإذا لم ينجح `ARWorldMap` بعد هذا الإصلاح فالمسار التالي هو محاذاة حائط/فتحة يدوية بنقطتين أو ثلاث نقاط بدل دمج مسح جديد بإحداثيات غير معروفة.
