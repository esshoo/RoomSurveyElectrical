# v1.9.25 — Build 46.1-HF4 Live Session Resume

## سبب الإصلاح

كان الإيقاف اليدوي يستدعي `RoomCaptureSession.stop(pauseARSession: false)`، أي أن جلسة `ARSession` الأصلية تبقى حية وتحافظ على نظام الإحداثيات. لكن زر الاستكمال كان يتجاهل ذلك ويعيد تشغيل الجلسة باستخدام `initialWorldMap` مع `resetTracking`، فيحوّل استكمالًا بسيطًا إلى محاولة Relocalization قد تبقى عالقة أو تفشل.

## المسار الجديد

### إيقاف يدوي داخل الشاشة نفسها

1. يتوقف RoomPlan فقط.
2. تستمر `ARSession` نفسها دون Pause أو Reset.
3. يحفظ المشروع والـARWorldMap كنسخة أمان.
4. عند الضغط على الاستكمال، يبدأ RoomPlan مباشرة على الجلسة الحية نفسها.
5. لا تظهر شاشة التعرف ولا تُطبّق إعدادات الصرامة في هذا المسار.

### خلفية التطبيق أو انقطاع الجلسة أو إعادة فتح المشروع

1. تُلغى صلاحية الاستكمال الحي.
2. تُحمّل `ARWorldMap` المحفوظة.
3. ينتظر التطبيق انتقال Tracking من `.limited(.relocalizing)` إلى `.normal`.
4. يبدأ RoomPlan بعد استعادة نظام الإحداثيات.

## مستويات الصرامة بعد الإصلاح

- **مرن:** ثبات Tracking في `.normal` هو شرط الاستكمال.
- **متوازن:** `.normal` مع Anchor/حائط، أو `.normal` المستقرة مدة إضافية إذا تأخر الدليل المساعد.
- **صارم:** `.normal` مع Anchor أو الحائط المرجعي، والموقع الاختياري إذا كان موثوقًا.

الحائط والـAnchor والموقع أدلة أمان إضافية، لكن لا يجوز أن تمنع الوضع المرن بعد أن يؤكد ARKit بنفسه استعادة الخريطة.

## الحدود

- لا يغيّر HF4 بيانات المشروع أو صيغة الملفات.
- لا يغيّر DXF/PDF/GLB.
- الحفظ الدوري ما زال Build 46.2.
- إعادة تصوير الأجزاء الضعيفة ما زالت Build 46.3.
