# 3ERoomElectrical v1.9.6 Build 23

## DXF

- Restores the strict AutoCAD R12 ASCII structure (`AC1009`) that opened correctly.
- Keeps all drawing entities in Model Space only.
- Does not emit `LAYOUT`, `VIEWPORT`, `OBJECTS`, group 67, or group 410.
- Shapes every non-ASCII label with CoreText and exports glyph outlines as closed classic `POLYLINE` records.
- Arabic therefore appears visually without storing Unicode bytes in the R12 file.
- ASCII dimensions and identifiers remain editable `TEXT` entities.
- The validator rejects any non-ASCII byte before the file is shared.

This trades editable Arabic text for maximum cross-program compatibility. The Arabic outlines remain ordinary selectable CAD geometry.

## Widget diagnosis

The previous diagnostic only proved that the `.appex` existed and that its Info.plist identity matched the host app. Build 23 additionally reads the signed `embedded.mobileprovision` from both the host app and the widget extension at runtime and reports:

- application identifier for each bundle,
- developer team identifier for each bundle,
- whether the widget has its own provisioning profile,
- whether the two profiles match the installed bundle identifiers and team.

This distinguishes a valid embedded file from an extension that iOS can actually register after Sideloadly signing.
