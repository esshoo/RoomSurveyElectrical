# 3ERoomElectrical v1.9.25 — Build 46.1-HF8

## Spatial coordinate safety, staged merge, unified 2D/3D and crash recovery

HF8 replaces the unsafe assumption that a visually aligned screenshot is enough to merge a fresh RoomPlan session into an existing project.

## Root causes corrected

1. **Unsafe six-degree camera transform**
   - HF7 used one fresh AR frame and the full camera transform after visual matching.
   - Pitch and roll differences could tilt the whole room and a different session origin could offset it.
   - HF8 permits only gravity-aligned yaw and translation. Reflection, scale, pitch and roll are rejected.

2. **Permissive wall merge**
   - A transformed wall that did not match an existing wall could be appended immediately.
   - HF8 requires at least one confirmed shared wall for resumed scans and rejects overlapping conflicts.
   - A failed candidate never changes the original project.

3. **2D and 3D used different geometry sources**
   - 2D used the merged project snapshots.
   - 3D continued loading the USDZ created by the first RoomPlan session.
   - After an accepted resumed merge, 3D is rebuilt from the same wall, opening, floor, furniture and electrical snapshots used by 2D.

4. **No app-owned checkpoint before a crash**
   - During an existing-project continuation, HF8 atomically saves a transformed candidate every five seconds.
   - Recovery is offered after relaunch, but the checkpoint is merged only after the same shared-wall and conflict checks.

## Coordinate contract

- ARKit, RoomPlan, persisted project snapshots and SceneKit use one right-handed, Y-up coordinate contract.
- Arabic right-to-left layout is limited to text and controls.
- Camera, AR, the 2D plan canvas, the original USDZ SceneKit viewer and the snapshot 3D viewer are isolated from the Arabic RTL layout direction. Text and controls remain RTL.
- The app never applies a horizontal or vertical image flip to a spatial matrix.

## Visual-assisted resume

The saved transparent image remains a guidance tool. It estimates the initial yaw and translation only. It is not itself permission to merge geometry.

The final RoomPlan result must pass all of the following:

- finite rigid transform;
- positive determinant, with no reflection or scale;
- gravity-aligned walls;
- at least one shared wall with compatible centre, direction and dimensions;
- no overlapping wall conflict.

If any check fails, the original project is kept unchanged and the new result remains an isolated recovery candidate.

## Recovery and save transaction

- The original `project.json` is not changed while a resumed scan is running.
- The periodic candidate is written to `resume-geometry-checkpoint.json` with atomic file replacement.
- A successful validated merge writes one final project transaction and removes the checkpoint.
- A crash or rejected merge leaves the original project intact and keeps the checkpoint for controlled recovery.

## Acceptance criteria

1. A resumed scan may add a new adjacent area only after finding at least one shared wall.
2. A second wall occupying the same physical place with an incompatible centre or orientation is rejected, not appended.
3. A camera pitch/roll mismatch cannot tilt the incoming room.
4. Arabic UI direction cannot change any AR/RoomPlan/SceneKit matrix.
5. After an accepted merge, 2D and 3D render the same project snapshot geometry.
6. Force-closing the app after at least five seconds of resumed scanning leaves a recoverable checkpoint.
7. Recovering a checkpoint cannot modify the original project unless shared-wall and conflict validation succeeds.

## Deferred

- Multi-point manual alignment editor remains part of the later scan-composition build.
- Build 46.2 periodic configurable world-map checkpoints has not started; HF8 only adds a fixed five-second geometry safety checkpoint for crash protection.
